# 观察者模式

## 1.概念

观察者模式，解决的是一种很常见的关系：

> 当一个对象状态变化时，需要自动通知多个关心他的对象

## 2.代码

先来看一个最基本的观察者模式的代码:

场景：用户能够订阅气象站，气象站产生天气消息，通知用户

气象站：

```java
import java.util.HashSet;
import java.util.Set;

public class WeatherStation {
    private Set<User> set = new HashSet<>();

    public void subscribe(User user){
        set.add(user);
    }

    public String getInfo(){
        int random =  (int)(Math.random()*2);
        if(random == 0){
            return "天气晴朗";
        }else{
            return "阴雨绵绵";
        }
    }

    public void publish() throws InterruptedException {
        while(true){
            String info = getInfo();
            System.out.println("气象站发布天气:" + info);
            for(User user:set){
                user.onEvent(info);
            }
            Thread.sleep(1000);
        }
    }

}
```

用户:

```java
import java.util.function.Consumer;

public class User {
    private final String name;
    private Consumer<String> consumer;

    public User(String name,Consumer<String> consumer){
        this.name = name;
        this.consumer = consumer;
    }

    public void onEvent(String message){
        consumer.accept(message);
    }
}
```

使用:

```java
public class Main {
    public static void main(String[] args) throws InterruptedException {
        WeatherStation weatherStation = new WeatherStation();
        User user = new User("张小豪",message -> {
            if(message.equals("天气晴朗")){
                System.out.println("出去玩");
            } else{
                System.out.println("呆在家");
            }
        });
        weatherStation.subscribe(user);
        weatherStation.publish();
    }
}
```

这个代码就是一个典型的观察者模式，但是气象站将`订阅`和`发布消息`也耦合在了一起。

根据`单一职责`的原则，我们应该让气象站只产生天气的消息，而订阅和发布消息，应该由"电视台"负责。而一般这个负责接收消息，转发消息的，有个专业的名字叫作事件总线。所以我们需要把`订阅`和`发布消息`的功能，放到事件总线上去。
