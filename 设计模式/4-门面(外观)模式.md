# 门面/外观模式

## 1.简单入门

外观模式是一种经典的结构型设计模式。它的核心思想是：**为复杂的子系统提供一个统一、简洁的高层接口，从而隐藏子系统内部的复杂性**。

生活举例: 我们去吃火锅，只需要点菜就行，对于买菜，烹饪这些复杂细节的过程我们是无感的。

代码举例:

比如我们有一个Tomcat的类，我们想使用，在`main`函数中就得这样写

```java
public class Tomcat {
    public void loadClass(){
        System.out.println("ClassLoader: 初始化类加载器");
    }
    public void connect(){
        System.out.println("Connector: 绑定端口 8080 ,启动协议处理器 ");
    }
    public void engine(){
        System.out.println("Engine: 启动容器，加载并部署Web应用");
    }
}

```

```java
public class Main {
    public static void main(String[] args) {
        Tomcat tomcat = new Tomcat();
        tomcat.loadClass();//需要客户端自己去调用
        tomcat.connect();
        tomcat.engine();
    }
}

```



在上面的代码例子中，我们用门面模式改造一下:

先写一个门面接口，然后`Tomcat`类去实现这个接口

```java
public interface ServerFacade {
    void start();
}

```

```java
public class Tomcat implements ServerFacade{
    public void loadClass(){
        System.out.println("ClassLoader: 初始化类加载器");
    }
    public void connect(){
        System.out.println("Connector: 绑定端口 8080 ,启动协议处理器 ");
    }
    public void engine(){
        System.out.println("Engine: 启动容器，加载并部署Web应用");
    }

    @Override
    public void start() {//以后客户端使用的时候，只需要调用start方法就可以了
        loadClass();
        connect();
        engine();
    }
}

```

## 2.JDK代码中的实际运用

JDK中有一个`Logger`类，比如我们想记录一条日志时，通常只需要这样一行代码

```java
Logger.getLogger("MyLogger").info("这是一条日志信息");
```

但是在这行代码的背后发生了很多，对于我们是无感的(下面的调用过程是AI总结的)

```
1. 获取 Logger（getLogger）
通过 LogManager 在命名树中按名字 "MyLogger" 查找或创建 Logger 实例，并从 logging.properties 加载级别、Handler、Filter 等配置；同时用反射拿到调用者 Class，决定类加载器和模块归属。
2. 便捷方法归一化（info → log）
info("这是一条日志信息") 内部直接调用 log(Level.INFO, msg)，所有 info/severe/warning/fine… 都汇聚到同一个核心方法，这是 Facade"统一入口"的体现。
3. 级别闸门（isLoggable）
比较当前有效级别（本 Logger 没设就继承父 Logger，最终根 Logger 默认 INFO）与要记的 Level，低于阈值就直接 return，零开销返回，不构造任何对象。
4. 构造 LogRecord
通过级别闸门后 new LogRecord(level, msg)，生成日志的载体对象，包含 level、message、时间戳、序号等字段，作为后续各子系统协作的 DTO。
5. 补全元数据（doLog）
给 record 填上 logger 名；再通过 getEffectiveLoggerBundle() 沿父子链找有效的 ResourceBundle（用于消息国际化），如果有就写入 record 的 resourceBundleName 和 resourceBundle。
6. 二次过滤（Filter）
进入 log(LogRecord)：先防御性再判一次级别，再用用户自定义的 Filter.isLoggable(record) 按内容决定要不要丢弃这条记录。
7. 分发到 Handler
取出当前 Logger 挂的 Handler 数组（典型是 ConsoleHandler/FileHandler），逐个调用 handler.publish(record)；Handler 内部会用 Formatter（如 SimpleFormatter/XMLFormatter）把 record 格式化成字符串，真正写到目的地，写失败则走 ErrorManager 兜底。
8. 沿父链传播
若 useParentHandlers=true，则切到 parent Logger 继续走其 Handler 数组；如此沿命名树向上冒泡，直到遇到 useParentHandlers=false 或根 Logger 为止——这就是子 Logger 没配 Handler 也能在控制台看到输出的原因（用的是 root 上挂的 ConsoleHandler）。
```
